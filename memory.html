Memory model

Memory for AI agents.

Every entry stored in Memotrix carries a memory_type — an exact-match payload filter, not a separate store. Three values are built in.

Semantic

Durable, general knowledge that doesn't depend on a specific moment or conversation — facts, preferences, documents.

memory.add_text("User prefers dark mode.", memory_type="semantic")
Episodic

What happened, and when — scoped to a conversation or task via session_id, another exact-match filter.

memory.add_text("Shipped hybrid search.", memory_type="episodic", session_id="2026-09-03")
Procedural

Standing rules and instructions the agent should keep following, independent of any one conversation.

memory.add_text("Always cite source_path.", memory_type="procedural")
HOW FILTERING WORKS

Both memory_type and session_id are exact-match filters on memory.search() — they narrow a similarity search rather than querying a separate table.

Building on the primitives

Higher-level memory patterns

Semantic, episodic and procedural memory are the only memory_type values documented today. Broader agent-memory concepts can still be built on top of them:

Working memory

Not a separate store — typically the current turn's context, held by the calling application, with only what's worth keeping written back via add_text.

Long-term memory

Semantic and procedural entries that are never deleted — durability comes from how long you keep the entry, not a separate memory type.

Multimodal memory

Any memory type populated from non-text sources — images, audio, video — via memory.add() and the extractors that back it.

SCOPE NOTE

These three patterns describe ways to use Memotrix's primitives — they are not separate memory_type values in the API. Only "semantic", "episodic" and "procedural" are documented.

Retrieval

Search combines similarity with filters

memory.search() runs a hybrid dense + sparse similarity search, then narrows results with any filters you pass.

Query

A natural-language question or task.

Hybrid search

Dense (HNSW) and sparse (BM25) results are combined.

Filters

memory_type, session_id and other payload filters narrow the set.

top_k hits

The closest matching entries are returned to the caller.

search.py
hits = memory.search(
    "how should answers be cited?",
    memory_type="procedural",
)

Files added with memory.add() keep their source_path, so results can be traced back to the original file.
